# Waifu Gallery 2.4.1 · Rust

Нативная галерея для Windows с Waifu.im v7. Интерфейс на egui/eframe, графика
через OpenGL, сеть через reqwest и rustls. Python для запуска не нужен.

Иконки навигации и действий нарисованы векторами. Собственная иконка Waifu Gallery
встроена в окно, панель задач, EXE и установщик Windows (ICO 16–256 px).

## Установка в Windows

Распакуй установочный ZIP и запусти **WaifuGallerySetup.exe**. Приложение
установится для текущего пользователя без прав администратора и появится в «Пуск»
и в списке установленных приложений Windows. Данные — в %LOCALAPPDATA%/WaifuGallery,
программа — в %LOCALAPPDATA%/Programs/WaifuGallery. Удаление сохраняет картинки
и настройки. Для переноса старых данных положи установщик в папку старой
портативной версии: настройки и images скопируются при первой установке.
Также установка доступна в «Настройки → Дополнительно» портативной версии.

## Автообновление

По умолчанию раз в 12 часов приложение проверяет последний стабильный GitHub Release.
Новый EXE скачивается в фоне, проверяется по SHA-256 GitHub и типу Windows x64,
затем применяется после закрытия приложения. Кнопка в верхней панели позволяет
сразу обновиться и перезапустить приложение. Предыдущий EXE сохраняется с суффиксом
.previous; при ошибке замены выполняется откат. Настройки и картинки не заменяются.
Проверку можно запустить вручную или отключить в «Настройки → Дополнительно».

Для публикации обновления: создай стабильный Release с тегом вида **v2.4.1**
и приложи **WaifuGallery.exe** из соответствующей сборки. Номер Cargo.toml должен
совпадать с тегом. GitHub должен предоставить digest SHA-256 для этого asset.
ZIP и установщик можно прикладывать дополнительно; updater использует именно
WaifuGallery.exe. Черновики и prerelease не устанавливаются. Без опубликованного
нового релиза обновление не появится.

## Запуск

Распакуйте Windows-архив и откройте **WaifuGallery.exe**. Настройки и папка images
по умолчанию находятся рядом с exe. Для другой папки данных:

```powershell
.\WaifuGallery.exe --data-dir "D:\Waifu"
```

Для переноса из Python положите старые settings.json и images рядом с exe
или укажите старую папку через --data-dir. Старые режим, тег, папка, режим
просмотра коллекции и пользовательский URL читаются при первом запуске.
Старый файл не перезаписывается: новая версия использует settings-rust.json.
Если прежнего тега нет в API, выбирается waifu.

## Возможности

- SFW / NSFW, актуальные теги и поиск по ним.
- Большой просмотр с масштабированием и лентой недавних кадров.
- Коллекция с поиском по имени файла и загрузкой миниатюр по мере прокрутки.
- PNG в полном разрешении, без перезаписи существующих файлов.
- Папки A: images/<режим>/<тег>, B: images, C: пользовательская.
- Источник и автор, если API передаёт эти сведения.
- Светлая, тёмная и системная тема; палитра и произвольный RGB-акцент.
- Использование акцента Windows и обновление системного оформления без перезапуска.
- Пользовательский JSON API с items[0].url или url. В этом режиме фильтры
  SFW/NSFW и тег нужно задавать в URL.

Клавиши: **Пробел / N** — следующая, **S** — сохранить,
**← / →** — история, **Ctrl+,** — настройки.

## Собственные аккаунты и синхронизация

Вход по логину и паролю, без обязательной почты. Разделы «Избранное» и «Альбомы»
синхронизируются с собственным сервером, как и тема, акцент и выбор цвета Windows.
По умолчанию используется https://waifudownload.hopto.org; сначала разверни сервер
по [инструкции для Ubuntu](deploy/README.md). Пароль аккаунта не записывается
в настройки; сессия хранится в Windows Credential Manager. При недоступном
хранилище сессия действует только до закрытия приложения.

Обновление между устройствами — примерно раз в 30 секунд или кнопкой
«Синхронизировать». Скачанные картинки, пути к папкам и параметры загрузки
остаются локальными. Новые PNG сохраняют ссылку, автора и категорию в соседнем файле .waifu.json:
не удаляй его, если нужна синхронизация избранного после повторного открытия.
Старые файлы без исходной ссылки тоже добавляются в избранное, но сохраняются
в разделе «На этом компьютере» и в облако не отправляются. Сервер не скачивает
изображения и не хранит их копии; если исходная ссылка перестанет работать,
открыть её из избранного не получится.

Без сети просмотр и локальное сохранение доступны. Очереди облачных действий
для работы без сети нет: ошибки показаны в разделе аккаунта, действие можно
повторить после восстановления связи. Не закрывай приложение, пока оформление
ожидает отправки. Одновременное изменение оформления разрешается последним
полученным сервером значением. Избранное и альбомы меняются отдельными операциями.
Почта не собирается; восстановление забытого пароля выполняет администратор сервера.

Интерфейс: компактная навигация, окно выбора категории, основные кнопки
«Новая картинка» и «Сохранить», настройки с вкладками «Оформление», «Сохранение»
и «Дополнительно».

## Быстродействие

Сеть, декодирование, сохранение и сканирование выполняются в фоновых потоках.
HTTP-клиент повторно использует соединения. Предзагрузка одного следующего кадра
включена по умолчанию и отключается в настройках.

История ограничена 48 изображениями и 96 МБ сжатых оригиналов. На GPU хранится
предпросмотр до 2048 px по длинной стороне; для сохранения используется оригинал.
Кэш коллекции ограничен 128 миниатюрами. Список коллекции виртуализирован:
отрисовываются видимые строки. В покое нет постоянного цикла 60 FPS.

Защита от чрезмерных размеров: файл до 32 МБ, декодирование до 128 МБ,
сторона до 16384 px. Очень большие файлы отображаются как ошибка.
Коллекция показывает до 2000 файлов, глубина сканирования до 6 папок;
символические ссылки не обходятся. Анимации открываются первым кадром.
Несохранённые изображения за пределами истории освобождаются из памяти.

Приложение читает API через Accept-Version: v7, поддерживает Retry-After и
до трёх повторов HTTP 429. Долгое ожидание сервера свыше минуты показывается
как ошибка с предложенным временем повторного запроса.

## Сборка

Нужны актуальный стабильный Rust и MSVC Build Tools с Windows SDK.

```powershell
cargo build --release --locked
cargo test --locked
cargo fmt --check
```

Исполняемый файл: target/release/waifu-gallery.exe.

Для проверки реального приложения (обращается к API, сохраняет PNG и снимки
тем в указанную отдельную папку, затем закрывается):

```powershell
cargo run --release --locked -- --smoke-test --data-dir "./smoke-data"
```

Файл smoke-result.txt должен начинаться с OK. Для обычного запуска из исходников:
cargo run --release -- --data-dir .

Windows — целевая и проверяемая платформа. Чтение акцента и системной темы
реализовано через Windows; перенос на другие ОС требует отдельной проверки.

API: https://docs.waifu.im/docs/getting-started/


Галерея 2.4.1: общая сетка сохранённых и избранных фотографий, поиск и размер карточек. Отдельный просмотр с лентой миниатюр, стрелками, масштабом и избранным. Esc возвращает к сетке. История раздела «Просмотр» не изменяется.


## Сторонние API
Настройки → Источники → Добавить API по ссылке. Введите адрес JSON API или прямой картинки, название и при наличии URL категорий. Источник сохраняется локально. Приложение ищет JSON-категории в tags/categories/endpoints рядом с адресом и поддерживает массивы строк, slug/name, items/data, разделение sfw/nsfw и hasNextPage (до 20 страниц).
Шаблоны: `{category}` / `{tag}`, `{mode}` (sfw/nsfw). Если выбранная категория уже стоит в последнем сегменте URL или параметре tag/category/IncludedTags/included_tags, после получения категорий приложение автоматически создаст шаблон. Неизвестные схемы требуют настройки ссылки; авторизация API пока не поддерживается. Категории можно добавить вручную.
Изображения: прямой ответ image/*, url/image_url/file_url/large_file_url/src, вложенные data/items/images/results/image/file. Относительные ссылки разрешаются относительно API. Фильтрацию 18+ выполняет источник: переключатель режима применим, если он включён в URL.

## Проверка сохранённых и избранных
На карточках и в просмотре отображается состояние фотографии. Для скачанных приложением файлов индекс строится в фоне из .waifu.json во всех активных папках сохранения. Совпадения исходных URL предотвращают повторное сохранение, в том числе после перезапуска. Избранное учитывает локальные отметки и аккаунт. Другой URL той же фотографии и файлы без метаданных могут не распознаться как совпадение.


В 2.4.1 при открытии фотографии в избранном, альбомах или сохранённом заранее загружаются следующий и предыдущий кадры. Отдельный фоновый поток, ограниченная очередь и кэш до 3 изображений / 64 МиБ (одна текущая картинка может превышать лимит). Переключатель: Настройки → Дополнительно → Предзагружать соседние фотографии. При закрытии просмотрщика очередь старой сессии игнорируется; уже начатый сетевой запрос может завершиться в фоне.

Миниатюры избранного заранее готовятся после синхронизации (первые 48 удалённых и 48 локальных), загружаются в три потока и сохраняются в cache/thumbnails. Кэш диска ограничен 256 миниатюрами / 32 МиБ. Для новых изображений при первом запуске требуется сеть. Автообновление использует новый адрес репозитория mabogma/waifu-downloader.
